# SykChw.github.io

Personal academic site. Plain Jekyll, dark theme only, deployed via GitHub
Actions. No Quartz, no Hugo, no client-side framework.

## Writing a new blog post (Obsidian workflow)

1. Open this repo as an Obsidian vault (or just the `blog/` folder) on your
   Mac.
2. Create a new file in `blog/` named `YYYY-MM-DD-slug.md`, e.g.
   `blog/2026-03-01-my-new-post.md`. The date prefix is how Jekyll figures
   out the publish date — same convention you used with Quartz.
3. Add front matter at the top:

   ```yaml
   ---
   title: "My New Post"
   date: 2026-03-01
   tags: [optimization, notes]
   ---
   ```

4. Write the body in plain Markdown. Supported out of the box:
   - **Math**: `$inline$` and `$$display$$` (MathJax).
   - **Mermaid diagrams**: fenced ```` ```mermaid ```` blocks, including
     `classDef`/`class` styling — rendered dark-themed automatically.
   - **Footnotes**: standard Markdown footnotes, `text[^1]` with
     `[^1]: note text` at the bottom. These get auto-relocated into the
     right-margin sidebar on wide screens.
   - **Citations**: add entries to `_bibliography/references.bib`, then
     cite with `{% cite somekey %}` inline. A References section renders
     automatically at the bottom of the post (only entries you actually
     cited). See [jekyll-scholar docs](https://github.com/inukshuk/jekyll-scholar)
     for locators, suppressing author names, etc.
   - **Obsidian callouts**: `>[!note]`, `>[!info]`, `>[!warning]`,
     `>[!question]` render as styled boxes, same syntax as Obsidian.
   - **Table of contents**: generated automatically from your `##`/`###`
     headings — no manual anchors needed.
   - **Images**: put files in `assets/images/` and reference with standard
     Markdown `![alt](/assets/images/file.png)`.
5. To keep a post as a draft (not published), add `published: false` to the
   front matter. Remove it when ready to go live.
6. `git add`, commit, push to `main`. GitHub Actions builds and deploys
   automatically — nothing to run locally.

## Previewing locally (optional)

If you want to preview before pushing:

```bash
brew install ruby
bundle install
mkdir -p _posts && cp blog/*.md _posts/   # same staging step CI does
bundle exec jekyll serve
```

Then visit `http://localhost:4000`. `_posts/` is gitignored — it's a build-time
copy of `blog/`, regenerated by CI on every push, so you never edit it directly.

## Structure

```
_config.yml           site config, jekyll-scholar settings
_layouts/              default, page, post
_includes/             citation.html (auto BibTeX blurb for "cite this post")
_plugins/callouts.rb   Obsidian-style callout rendering
_bibliography/         references.bib (jekyll-scholar source)
_data/news.yml         itemized news entries, grouped by month on /news/
assets/css/main.css    all styling — dark theme only, never add light mode
assets/js/             toc.js, sidenotes.js, blog-search.js
blog/                  blog posts you write/edit directly (Jekyll's _posts/
                       is generated from this at build time — see below)
index.html             home page (bio + portrait)
blog.html              blog index with tag filter + search
news.html              news page
research.html          publications page
```

## Adding a publication

Add a BibTeX entry to `_bibliography/references.bib`, then add a
`.pub-entry` block to `research.html` following the existing SETA example.

## Deployment

`.github/workflows/deploy.yml` builds with `bundle exec jekyll build` and
deploys via `actions/deploy-pages`. Enable GitHub Pages with source set to
"GitHub Actions" in repo settings — no `gh-pages` branch needed.
